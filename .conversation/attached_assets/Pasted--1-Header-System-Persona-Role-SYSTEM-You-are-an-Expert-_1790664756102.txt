# 3. Product Goal

Build an **AI-Powered Agriculture Crop Advisory Assistant**. Farmers struggle with crop diseases, unpredictable weather, and fluctuating market prices, leading to crop losses and reduced income. This application solves this by providing a unified platform where farmers can detect crop diseases via computer vision (image upload), receive actionable weather-based farming alerts, and get data-driven suggestions on the best time and market to sell their crops.

# 4. Mandatory Features

* **Computer Vision Disease Detection:** Users can upload photos of affected plant leaves/crops. The AI will identify the disease, assess severity, and provide a step-by-step treatment plan.
* **Weather-Based Farming Alerts:** Users input their crop type, growth stage, and current/forecasted weather anomalies (e.g., "3 days of heavy rain"). The AI provides immediate protective actions and long-term agronomic advice.
* **Market Price & Timing Oracle:** Users input their crop, yield quantity, and local market trends. The AI evaluates holding vs. selling strategies and suggests target markets to maximize income.
* **Historical Advisory Dashboard:** A centralized dashboard that stores and categorizes all past AI advisories (Disease, Weather, Market) for ongoing reference.
* **Secure Authentication & Data Isolation:** Multi-tenant architecture ensuring each farmer's farm data and advisory history is strictly isolated.

# 10. Database Schema (Production SQL for PostgreSQL)

```sql
CREATE EXTENSION IF NOT EXISTS "uuid-ossp";

CREATE TABLE users (
    id UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
    email VARCHAR(255) UNIQUE NOT NULL,
    password_hash VARCHAR(255) NOT NULL,
    full_name VARCHAR(255) NOT NULL,
    location VARCHAR(255),
    created_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE farms (
    id UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
    user_id UUID REFERENCES users(id) ON DELETE CASCADE,
    primary_crops TEXT[] NOT NULL,
    farm_size_hectares DECIMAL,
    created_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP
);

CREATE TYPE advisory_category AS ENUM ('disease', 'weather', 'market');

CREATE TABLE advisories (
    id UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
    user_id UUID REFERENCES users(id) ON DELETE CASCADE,
    category advisory_category NOT NULL,
    crop_type VARCHAR(255) NOT NULL,
    user_inputs JSONB NOT NULL,
    ai_response JSONB NOT NULL,
    image_url TEXT, -- Optional, for disease tracking
    created_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP
);

CREATE INDEX idx_advisories_user_id ON advisories(user_id);
CREATE INDEX idx_advisories_category ON advisories(category);

```

# 11. Row Level Security (RLS) / Data Isolation Rules

Strict data isolation must be enforced at the database level. Implement the following PostgreSQL RLS policies:

```sql
ALTER TABLE users ENABLE ROW LEVEL SECURITY;
ALTER TABLE farms ENABLE ROW LEVEL SECURITY;
ALTER TABLE advisories ENABLE ROW LEVEL SECURITY;

-- Users can only read and update their own profile
CREATE POLICY "Users access own profile" ON users FOR ALL USING (id = current_setting('app.current_user_id')::UUID);

-- Users can only access their own farm data
CREATE POLICY "Users access own farm" ON farms FOR ALL USING (user_id = current_setting('app.current_user_id')::UUID);

-- Users can only access their own advisories
CREATE POLICY "Users access own advisories" ON advisories FOR ALL USING (user_id = current_setting('app.current_user_id')::UUID);

```

*(Note for Node.js implementation: Set the session variable `app.current_user_id` inside your database transaction middleware before executing queries, or handle standard foreign-key isolation securely in the backend controllers).*
